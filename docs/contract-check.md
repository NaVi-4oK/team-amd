# Проверка контрактов колодой покера

До реализации проверьте, может ли команда ответить на каждую карту только по контракту: какой JSON-запрос приходит, что возвращается, создаётся ли Job и в каком он состоянии. Для каждого ответа указано место в документации. Если поведение сознательно не поддерживается, причина должна быть зафиксирована в ADR.

## Колода K1–K10

| Карта | Атака на проект | Ответ контракта | Где это зафиксировано |
|---|---|---|---|
| K1 Двойной клик | Импорт или обработка отправлены повторно с тем же ключом идемпотентности и параметрами | Возвращается тот же Job; повторный внешний запрос или повторное создание результата не запускаются | `tool-contract.md` → «Общие правила»; ADR 0002 → «Решение» |
| K2 Ответ потерялся | CLI-команда выполнена, но пользователь не получил ответ и повторил её | Повтор с тем же ключом и параметрами возвращает тот же Job. Состояние проверяется командой `job-status` по `jobId` | `cli.schema.json` → JSON Pointer `$defs.jobStatusCommand` и `$defs.jobStatus`; ADR 0002 → «Решение» |
| K3 Неизвестная операция | В JSON указан неизвестный `command` | Команда не соответствует `$defs.request`; Job не создаётся. CLI возвращает JSON-ошибку `invalid_command` | `cli.schema.json` → `$defs.request`, `$defs.error` |
| K4 Кривые параметры | Пропущено обязательное поле, передан неверный тип или значение вне перечисления | Запрос отклоняется до создания Job. Ошибка содержит `code`, `message` и, если доступно, `details` с указанием поля | `cli.schema.json` → определения `importCommand`, `processCommand`, `queryCommand`, `error`; `tool-contract.md` → «Кто что проверяет» |
| K5 Воскрешение | Повторно запускают уже завершённый импорт или обработку | Тот же ключ и те же параметры возвращают прежний Job, включая конечное состояние. Новый запуск требует нового ключа; обработка создаёт отдельный результат и не меняет исходный набор | `tool-contract.md` → «Общие правила», «Tool 2 — Processing Tool»; ADR 0002 → «Решение» |
| K6 Отмена | Пользователь просит остановить выполняющийся импорт или обработку | Отмена не поддерживается: в CLI нет команды отмены. Уже выполняющийся Job продолжает работу до `Completed` или `Failed`; повторное использование того же Job запрещено | ADR 0002 → «Рассмотренные варианты» (отмена не включена в контракт текущей версии) |
| K7 Огромный вход | Запрошен период или объём данных намного больше обычного | CLI проверяет типы и границы времени; HAPI-ограничение отображается как `intermagnet_request_rejected`. Если полный ответ нельзя сохранить, Import Tool возвращает `storage_error`; частичный набор не публикуется | `tool-contract.md` → внешний HAPI-контракт, Tool 1 → «Ошибки»; `cli.schema.json` → `$defs.error` |
| K8 Чужой или несуществующий ID | Запрошен отсутствующий `datasetId` или Job, созданный другим пользователем | Несуществующий локальный набор даёт `dataset_not_found`, неизвестный Job — `job_not_found`. Идентификатор другого пользователя неприменим: приложение локальное и рассчитано на одного исследователя; серверного доступа и чужих клиентов нет | `tool-contract.md` → Tool 3 и Tool 1 «Ошибки»; ADR 0001 → «Последствия» |
| K9 Перезапуск программы | Программа завершилась, пока Job находился в `Downloading` или `Processing` | Незавершённый Job после запуска программы помечается `Failed`; частичный набор не считается готовым. Повтор с тем же ключом возвращает этот Job; для новой попытки нужен новый ключ | ADR 0002 → «Последствия» и «Решение»; `architecture.md` → «Job и переходы» |
| K10 Внешний сервис | INTERMAGNET не отвечает, возвращает ошибку или несовместимые метаданные | После ограниченных повторов Job становится `Failed` с `intermagnet_unavailable`; ответ источника, не прошедший проверку, не публикуется как готовый набор. Сопоставления HAPI-ошибок приведены в контракте Import Tool | `tool-contract.md` → «Внешний контракт INTERMAGNET HAPI», Tool 1 → «Ошибки» |

## Что предложил ИИ

### Промпт

> Ты атакующий на ревью контрактов. Изучи описание проекта, `docs/tool-contract.md`, `docs/api/cli.schema.json`, ADR и колоду K1–K10 из `docs/contract-check.md`. Предложи ровно три дополнительные ситуации, которых нет в K1–K10 и на которые документы не дают однозначного ответа. Для каждой укажи конкретный запрос или условие, вопрос атакующего и недостающий ответ контракта. Не повторяй уже закрытые случаи и не выдумывай поведение, которого нет в документах.

### Находки и решения команды

| Находка ИИ | Решение | Что изменили или почему отклонили |
|---|---|---|
| HAPI вернул статус успеха, но тело ответа обрезано, не разбирается или противоречит метаданным `info`. | Приняли | В `tool-contract.md` добавлена ошибка `intermagnet_invalid_response`: Job завершается `Failed`, сырой набор не публикуется. Код добавлен и в перечень JSON-ошибок в `cli.schema.json`. |
| Новые наборы появляются между страницами запроса, и продолжение по `cursor` может пропустить или повторить элементы из-за незафиксированной сортировки. | Приняли | В `tool-contract.md` зафиксированы сортировка по `created_at` по убыванию, затем по `dataset_id` по возрастанию, снимок с верхней границей на первой странице и размер страницы по умолчанию 100, максимум 1000. `limit` в `cli.schema.json` ограничен значениями 1–1000. |
| Одинаковый запрос импорта отправлен с новым ключом идемпотентности, хотя такой набор уже сохранён. | Отклонили | Ключ идемпотентности защищает от повторов одной операции, а не выполняет дедупликацию содержимого. Новый ключ считается новым запросом: исследователь может намеренно повторно получить обновлённые данные или отдельный снимок происхождения. Дедупликация по содержимому не является требованием проекта. |
