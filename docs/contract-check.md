| Карта | Атака на проект | Ответ контракта | Где зафиксировано |
|---|---|---|---|
| K1 Двойной клик | Повтор с одинаковым ключом и параметрами | Возвращается прежний Job без повторного выполнения | tool-contract.md, ADR 0002 |
| K2 Ответ потерялся | Пользователь повторяет уже принятую команду | Возвращается прежний Job; состояние можно запросить по Job ID | ADR 0002, cli.schema.json |

| K4 Кривые параметры | Пропущено обязательное поле или передано неверное значение | Новый Job не создаётся; возвращается ошибка с указанием поля | tool-contract.md, методы validate() |
| K5 Воскрешение | Повторный запуск завершённого задания | Прежний Job не запускается; новый запрос требует нового ключа | core/job.py, ADR 0002 |
| K6 Отмена | Пользователь просит остановить Job | Отмена не поддерживается текущей архитектурой | ADR 0002 |

| K8 Чужой или неизвестный ID | Запрошен несуществующий набор или Job | dataset_not_found или job_not_found; чужие пользователи неприменимы к локальному однопользовательскому приложению | core/datasets.py, core/repository.py |
| K9 Перезапуск | Программа остановилась до завершения Job | Незавершённый Job переводится в Failed с job_interrupted; повтор не запускает его заново | ADR 0002, core/dispatcher.py |
| K10 Внешний сервис | INTERMAGNET недоступен или вернул ошибку | Ошибка сопоставляется с доменным кодом; неуспешный результат не публикуется | tools/import_tool.py, tool-contract.md |

> запрос или условие, вопрос атакующего и недостающий

## Практика 3 — проверка Job

### Обычный путь

Импорт:

```text
Created → Downloading → Completed
```

Обработка:

```text
Created → Processing → Completed
```

Оба сценария проверяются тестом
`test_successful_path` в `tests/test_job.py`.

Также проверяется полный сценарий:

```text
Import Tool
    → raw dataset
    → Processing Tool
    → processed dataset
    → Query Tool
```

Интеграционный тест:
`test_full_import_process_query_workflow`
в `tests/test_query_tool.py`.

## Проверка злодейств З1–З6

| Злодейство | Проверка | Результат | Тест |
|---|---|---|---|
| З1 — двойная работа | Повторный start для работающего Job | Отклонено | test_z1_double_start |
| З2 — вечная работа | Восстановление прерванного Job | Job переходит в Failed | test_z2_interrupted_job, test_recover_interrupted_jobs |
| З3 — отменённое стало готовым | Отмена или удаление Job | Неприменимо | Отмена и удаление не поддерживаются |
| З4 — два итога | Попытка завершить Failed как Completed | Отклонено | test_z4_failed_to_completed |
| З5 — успех без работы | Попытка завершить Created как Completed | Отклонено | test_z5_complete_without_start |
| З6 — повтор успешного | Попытка запустить Completed | Отклонено | test_z6_restart_completed |

Проверки переходов выполняются самим Job.

Недопустимая операция возвращает
invalid_job_transition и не изменяет состояние.

З2 проверяется через имитацию восстановления Job
в памяти, без фактического перезапуска процесса.

З0 — обычный путь — проверяется отдельно:
успешный импорт и обработка не нарушены
ограничениями переходов.

## Дополнительный аудит с помощью ИИ

После реализации компонентов доменного ядра
проведён разбор потенциальных обходов контрактов
и пограничных сценариев.

### Находка 1. Конфликт идемпотентности скрывается валидацией

Исходное поведение:

1. Корректный запрос создаёт Job с ключом key-001.
2. Повторный запрос использует тот же ключ,
   но передаёт некорректные изменённые параметры.
3. Валидация возвращает ошибку параметров раньше,
   чем проверяется конфликт ключа.

Исправление:

Проверять существующий ключ до валидации Tool.
При создании нового Job повторно выполнять
атомарную проверку ключа.

Тесты:

- test_idempotency_conflict_before_validation
- test_replay_does_not_validate_again

### Находка 2. Job остаётся в Created после прерывания

Исходное поведение:

1. Job создаётся в состоянии Created.
2. Приложение прерывается до запуска Tool.
3. Восстановление обрабатывает только рабочие
   состояния Downloading и Processing.

Исправление:

Включить Created в восстановление незавершённых Job.
Переводить задание в Failed с job_interrupted.

Тест:

- test_recover_created_job

### Находка 3. Некорректные JSON-параметры

Исходное поведение:

Некорректное значение, например NaN,
может вызвать обычное исключение при формировании
сигнатуры идемпотентного запроса.

Исправление:

Обрабатывать ошибки сериализации параметров
и возвращать DomainError с кодом invalid_parameters
и указанием поля parameters.

Тест:

- test_non_json_parameters_are_rejected

## Ограничения проверки

- Реальный INTERMAGNET не вызывается.
- Используются тестовые ответы внешнего источника.
- Хранилища работают в оперативной памяти.
- Реальное восстановление между перезапусками
  пока не реализовано.
- Пользовательский CLI пока не реализован.
- Полная проверка метаданных и научного качества
  измерений относится к дальнейшей разработке.
- Курсоры пагинации пока не имеют срока жизни.
- Processing Tool содержит демонстрационный метод
  count_records.

Успешное прохождение тестов подтверждает проверенные
сценарии доменного ядра, но не означает завершение
всей целевой программы.
