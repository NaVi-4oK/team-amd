# Проверка согласованности контрактов (изм)

Документ задаёт сценарии проверки проекта перед реализацией и приёмкой. Он не утверждает, что проверки уже выполнены. Сверяйте результаты трёх представлений: архитектуры, OpenAPI и контрактов Tool.

## Сценарии

| Сценарий | Ожидаемый результат | Проверяемые документы |
|---|---|---|
| Импорт корректного запроса | Создан Import Job; запрос отправлен в INTERMAGNET; исходный ответ и происхождение сохранены в локальной БД; Job становится `Completed`; возвращён `raw_dataset_id` | Архитектура, OpenAPI `/imports`, контракт Import Tool |
| Повтор импорта с тем же ключом и телом | Возвращается прежний Job, повторный внешний запрос не запускается | OpenAPI, контракт Import Tool |
| Повтор импорта с тем же ключом и другим телом | `409` / `idempotency_conflict`, новый Job не создаётся | OpenAPI, контракт Import Tool |
| Источник недоступен или отклоняет запрос | Job становится `Failed`; сырой набор не показывается как завершённый; сообщение безопасно и не содержит секретов | Архитектура, контракт Import Tool, OpenAPI `/jobs/{jobId}` |
| Источник вернул корректный пустой набор | Импорт успешен: `Completed`, `record_count = 0`; пустой набор можно найти и прочитать локально | Контракт Import Tool, OpenAPI datasets |
| Запрос импорта некорректен | Запрос отклоняется до вызова INTERMAGNET и без созданного Job | OpenAPI `/imports`, контракт Import Tool |
| Обработка существующего сырого набора | Создан отдельный Processing Job; результат сохранён под новым ID со ссылкой на исходный набор; сырой набор не меняется | Архитектура, OpenAPI `/processing`, контракт Processing Tool |
| Обработка с неизвестным методом или неверными параметрами | Ошибка контракта; готовый результат не создаётся | OpenAPI `/processing`, контракт Processing Tool |
| Во время обработки произошёл сбой | Job становится `Failed`; частичный результат не опубликован; сырой набор доступен | ADR 0001/0002, контракт Processing Tool |
| Повторный запуск обработки | Создаётся новый Job и новый результат, связанные с тем же сырым набором | ADR 0002, архитектура, контракт Processing Tool |
| Чтение сырых данных без сети | Данные возвращаются из локальной БД; внешний API не вызывается | Архитектура, OpenAPI datasets/records, контракт Query Tool |
| Чтение результата обработки | Возвращаются обработанные данные и ссылка на исходный сырой набор | OpenAPI datasets, контракт Query Tool |
| Чтение неизвестного набора | Возвращается `404` / `dataset_not_found`; записи не создаются и внешний API не вызывается | OpenAPI `/datasets/{datasetId}`, контракт Query Tool |
| Локальная БД недоступна | Возвращается `storage_error`/`503`; Job не становится `Completed` без сохранённого набора | OpenAPI, контракты всех Tool, ADR 0001 |
| Запрещённый переход Job | Возвращается `invalid_job_transition`; исходное состояние Job не изменяется | Архитектура, ADR 0002 |

## Инварианты

1. Сырой и обработанный наборы имеют разные идентификаторы и не перезаписывают друг друга.
2. У обработанного набора есть ссылка на сырой источник, метод и параметры обработки.
3. `Completed` означает, что данные и метаданные соответствующего результата сохранены локально.
4. Только Import Tool обращается к API INTERMAGNET. Processing Tool и Query Tool работают только с локальной БД.
5. Ошибки внешнего API, обработки, валидации и хранилища различимы по коду.
6. Поля формата INTERMAGNET и содержание результата обработки не считаются подтверждёнными, пока команда не выбрала и не описала их.

## Перед сдачей

- Сверить имена полей OpenAPI с входами/выходами Tool.
- Убедиться, что каждый ожидаемый код ошибки из Tool имеет соответствующее HTTP-представление в OpenAPI.
- Проверить, что импорты сохраняют исходные данные, а обработка их не изменяет.
- Проверить, что схема не описывает удалённое размещение программы или внешнюю БД.
- Заменить пометки о нерешённых решениях только после согласования реального API INTERMAGNET, формата ответа, БД и методов обработки.
