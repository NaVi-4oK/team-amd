# Контракт Tool

В локальной программе предусмотрены три Tool. Первый загружает сырые записи из одного внешнего API, второй обрабатывает ранее сохранённый сырой набор, третий читает сырые или обработанные данные из локальной базы. Интерфейсы независимы от конкретного поставщика API, движка базы и метода обработки.

## Общие правила

- Внешний источник выбирается конфигурацией `ObservatoryApiTool`; пользователь не передаёт произвольный URL.
- Один внешний API используется для запроса данных разных обсерваторий.
- Сырые и обработанные наборы сохраняются в локальной базе. Сохранение выполняет локальный сервис через репозитории после успешного ответа Tool.
- Обработанные данные создаются отдельно и ссылаются на исходный сырой набор. Tool обработки не изменяет оригинал.
- Tool чтения работает только с локальной базой: он не вызывает внешний API и не изменяет наборы.

Общий формат отказа:

```text
ToolError
    code: string
    message: string
    field: string | null
```

Сообщения безопасны для показа пользователю и не содержат токены, пароли или другие секреты.

## Tool 1. `ObservatoryApiTool`

Загружает сырые геомагнитные записи для выбранных обсерваторий из единого внешнего API.

### Вход

```text
RawImportRequest
    observatory_ids: list[string]
    components: list[string]
    start: datetime
    end: datetime
```

Сервис до создания задания проверяет непустые списки, формат дат, наличие часового пояса и `start <= end`. Tool проверяет поддержку запроса внешним API и корректность его ответа.

### Результат

```text
RawDataBatch
    provider_id: string
    observatory_ids: list[string]
    requested_start: datetime
    requested_end: datetime
    retrieved_at: datetime
    response_metadata: object  # только метаданные, возвращённые API
    records: list[RawRecord]

RawRecord
    observatory_id: string
    payload: object  # запись API без научного исправления или заполнения
```

Tool сохраняет значения и структуру записей источника без исправления чисел и заполнения пропусков. Он может привести сетевой ответ к транспортному формату `RawRecord`, но исходное содержимое каждой записи остаётся в `payload`. `response_metadata` содержит только сведения, которые действительно вернул API; Tool не объявляет данные полными, если источник этого не подтвердил. Локальный сервис сохраняет весь `RawDataBatch` как сырой набор.

Пустой `records` — допустимый ответ API: импорт завершается успешно и сохраняется набор с нулём записей.

### Ошибки

| Код | Когда возвращается |
|---|---|
| `invalid_import_parameters` | Запрос не поддерживается API или неверен для данного источника |
| `access_denied` | API отказал в доступе |
| `external_api_unavailable` | Сетевой сбой, тайм-аут или исчерпаны ограниченные повторы временной ошибки |
| `invalid_external_response` | Ответ невозможно разобрать или он не соответствует ожидаемому формату |
| `response_too_large` | Ответ превысил настроенный лимит чтения |

## Tool 2. `GeomagneticProcessingTool`

Обрабатывает сырой набор по запросу пользователя и возвращает отдельный набор для дальнейшей интерпретации. Конкретные алгоритмы и состав результата команда ещё должна согласовать.

### Вход

```text
ProcessingRequest
    raw_dataset_id: string
    method_id: string
    parameters: object
    raw_records: list[RawRecord]
```

Локальный сервис проверяет наличие исходного набора в базе, загружает его и передаёт Tool вместе с параметрами метода. `method_id` и `parameters` не задают заранее неподтверждённый алгоритм; их допустимые значения описываются для выбранного метода.

### Результат

```text
ProcessedDataBatch
    raw_dataset_id: string
    method_id: string
    parameters: object
    processed_at: datetime
    records: list[object]
    metadata: object
```

`records` содержат результат выбранного метода в согласованном с ним формате. `metadata` содержит поясняющую информацию, нужную для интерпретации результата. Локальный сервис создаёт новый идентификатор processed-набора и сохраняет результат и ссылку на `raw_dataset_id` в локальной базе. Сырой набор остаётся неизменным.

### Ошибки

| Код | Когда возвращается |
|---|---|
| `invalid_processing_parameters` | Метод неизвестен или его параметры недопустимы |
| `invalid_raw_data` | Входные записи не подходят для выбранного метода; пустой вход отклоняется только если метод требует хотя бы одну запись |
| `processing_failed` | Во время обработки произошла ожидаемая ошибка метода |

## Tool 3. `LocalDataQueryTool`

Читает список наборов, сведения о выбранном наборе и его записи из локальной базы. Tool предоставляет общий интерфейс чтения для сырых и обработанных наборов.

### Поиск наборов

```text
DatasetListQuery
    dataset_kind: "raw" | "processed" | null
    observatory_id: string | null
    offset: integer
    limit: integer

DatasetListPage
    items: list[DatasetSummary]
    offset: integer
    limit: integer
    total: integer | null

DatasetSummary
    dataset_id: string
    dataset_kind: "raw" | "processed"
    created_at: datetime
    metadata: object
```

`list_datasets(query: DatasetListQuery) -> DatasetListPage` возвращает страницу метаданных наборов, найденных локально. Фильтры необязательны.

### Вход

```text
DatasetQuery
    dataset_id: string
    dataset_kind: "raw" | "processed"
    observatory_id: string | null
    component: string | null
    start: datetime | null
    end: datetime | null
    offset: integer
    limit: integer
```

`query_records(query: DatasetQuery) -> DatasetPage` возвращает записи выбранного набора с фильтрами и пагинацией.

Сервис проверяет формат фильтров и ограничивает размер страницы. Tool обращается только к локальной базе и выполняет чтение без изменения данных.

### Результат

```text
DatasetPage
    dataset_id: string
    dataset_kind: "raw" | "processed"
    metadata: object
    records: list[object]
    offset: integer
    limit: integer
    total: integer | null
```

Для raw-набора записи возвращаются в исходном транспортном представлении; для processed-набора — в формате, сохранённом выбранным методом обработки. Пагинация позволяет читать большие наборы частями.

### Ошибки

| Код | Когда возвращается |
|---|---|
| `invalid_query` | Некорректный фильтр, период или параметры страницы |
| `dataset_not_found` | Набор отсутствует в локальной базе или не соответствует запрошенному типу |
| `local_storage_unavailable` | Локальная база недоступна или не смогла выполнить чтение |

## Кто и что проверяет

| Слой | Проверки |
|---|---|
| Интерфейс и локальный сервис | Обязательные поля, формат периода и фильтров, существование выбранного набора, идемпотентность команд импорта/обработки |
| `ObservatoryApiTool` | Поддержка запроса внешним API, структура ответа и сетевые ограничения |
| `GeomagneticProcessingTool` | Наличие и допустимость параметров выбранного метода, пригодность входных записей для него |
| `LocalDataQueryTool` | Допустимость условий чтения и доступность указанного набора в локальной базе |
| Локальный сервис и репозитории | Сохранение сырых/обработанных данных и Job в локальной базе; результат и `Completed` фиксируются атомарно |

Ошибка импорта или обработки переводит соответствующий Job в `Failed`. Ошибка чтения возвращается пользователю непосредственно: для чтения Job не создаётся. Точные названия внешнего API, движка локальной базы, методов обработки и структуры processed-записей остаются предметом решения команды.
