# Контракт Tool (изм)

Tool — внутренняя операция локальной программы. Локальный API или сервис заданий вызывает Tool, проверяет переходы Job и передаёт результат исследователю. Tool возвращает типизированный результат либо ошибку; он не меняет Job напрямую.

Контракт фиксирует поведение приложения. Детали протокола INTERMAGNET и алгоритмы обработки необходимо согласовать до реализации.

## Общие правила

- Время в запросах задаётся с часовым поясом; для временных рядов используется UTC, если это подтверждено форматом источника.
- Идентификаторы наборов и Job выдаёт программа.
- Ошибка содержит стабильный `code`, безопасное для пользователя сообщение и при наличии `details`; секреты и полный чувствительный ответ источника в сообщении не возвращаются.
- Для команд импорта и обработки локальный API требует ключ идемпотентности: повтор с тем же ключом и теми же параметрами возвращает прежний Job; повтор с другими параметрами отклоняется с `idempotency_conflict`.
- Запись данных и завершение соответствующего Job должны фиксироваться согласованно: завершённый набор не указывает на отсутствующие или частично записанные данные.
- Ошибки локального хранилища отличаются от ошибок внешнего API и ошибок в параметрах.

## Tool 1 — INTERMAGNET Import Tool

Назначение: получить сырой набор геомагнитных измерений из API INTERMAGNET и сохранить его в локальной БД. Tool не выполняет научную обработку, нормализацию значений или заполнение пропусков.

### Вход

```text
ImportRequest {
  observatory_id: string
  time_range: { start: datetime, end: datetime }
  components: list<string>
  idempotency_key: string
}
```

Идентификаторы обсерваторий, допустимые компоненты, границы периода и формат времени должны соответствовать подтверждённым возможностям INTERMAGNET. Поля выше — контракт приложения, а не утверждение о названиях полей внешнего API.

### Успешный результат

```text
ImportResult {
  job_id: string
  raw_dataset_id: string
  source: "INTERMAGNET"
  observatory_id: string
  requested_time_range: { start: datetime, end: datetime }
  retrieved_at: datetime
  record_count: integer
  source_metadata: object
}
```

Сырые данные и доступные метаданные ответа сохраняются как получены, в форме, пригодной для последующего чтения/обработки. Схема `source_metadata` и представление сырого содержимого фиксируются после проверки внешнего контракта. Пустой набор может быть успешным ответом источника: тогда `record_count = 0`, а Job завершается `Completed`.

### Ошибки

| Код | Когда возникает | Изменение данных |
|---|---|---|
| `invalid_import_request` | Некорректный период, пустой список или неверное значение параметра | Job не создаётся |
| `unsupported_observatory_or_component` | Обсерватория/компонента не поддерживается подтверждённым контрактом | Job не создаётся либо завершается `Failed`, если выяснилось при проверке ответа |
| `intermagnet_unavailable` | Сетевой тайм-аут, недоступность или временная ошибка внешнего API после ограниченных повторов | Сырой набор не публикуется |
| `intermagnet_rejected_request` | INTERMAGNET отклонил запрос | Сырой набор не публикуется |
| `invalid_source_response` | Ответ не соответствует ожидаемому внешнему контракту или неполон для сохранения | Сырой набор не публикуется |
| `storage_error` | Не удалось полностью сохранить набор и Job | Транзакция откатывается, если это поддержано хранилищем; иначе состояние восстановления явно фиксируется |

## Tool 2 — Processing Tool

Назначение: обработать сохранённый сырой набор по выбранному методу и сохранить отдельный результат. Конкретный перечень алгоритмов не задан этим контрактом.

### Вход

```text
ProcessingRequest {
  raw_dataset_id: string
  method_id: string
  parameters: object
  idempotency_key: string
}
```

### Успешный результат

```text
ProcessingResult {
  job_id: string
  processed_dataset_id: string
  source_raw_dataset_id: string
  method_id: string
  parameters: object
  completed_at: datetime
  record_count: integer
  result_metadata: object
}
```

Обработанный набор ссылается на исходный сырой набор. Исходный набор остаётся неизменным. Перезапуск обработки — новый Job и новый `processed_dataset_id`, даже если выбран тот же метод.

### Ошибки

| Код | Когда возникает | Изменение данных |
|---|---|---|
| `invalid_processing_request` | Не задан метод или некорректны параметры запроса | Job не создаётся |
| `raw_dataset_not_found` | Сырой набор отсутствует в локальной БД | Job не создаётся |
| `method_not_supported` | Метод не зарегистрирован в программе | Job не создаётся |
| `processing_input_invalid` | Данные не подходят выбранному методу | Job завершается `Failed`, готовый результат не публикуется |
| `processing_failed` | Метод завершился вычислительной ошибкой | Job завершается `Failed`, частичный результат не публикуется |
| `storage_error` | Результат или состояние Job не удалось сохранить | Готовый результат не публикуется |

## Tool 3 — Local Data Query Tool

Назначение: читать сырые и обработанные наборы из локальной БД. Tool не обращается к INTERMAGNET и не запускает обработку.

### Вход

```text
DatasetQuery {
  dataset_kind: "raw" | "processed"
  dataset_id: string?                 // если указан, вернуть конкретный набор
  observatory_id: string?             // фильтр для сырых наборов
  source_raw_dataset_id: string?      // фильтр обработанных результатов
  time_range: { start: datetime, end: datetime }?
  components: list<string>?
  limit: integer
  cursor: string?
}
```

Программа проверяет, что `limit` положителен и не превышает согласованный предел, временной интервал корректен, а фильтры допустимы для выбранного вида набора.

### Успешный результат

```text
DatasetPage {
  items: list<DatasetSummary>
  next_cursor: string?
}

DatasetSummary {
  dataset_id: string
  dataset_kind: "raw" | "processed"
  observatory_id: string?
  time_range: { start: datetime, end: datetime }?
  record_count: integer
  created_at: datetime
  provenance: object
}
```

Чтение конкретного набора возвращает его содержимое и метаданные. Список возвращает страницу кратких описаний. Порядок сортировки и максимальный размер страницы должны быть одинаковыми в API и реализации.

### Ошибки

| Код | Когда возникает |
|---|---|
| `invalid_query` | Неверные фильтры, диапазон, курсор или предел страницы |
| `dataset_not_found` | Указанный набор не найден локально |
| `storage_error` | Локальная БД недоступна или чтение завершилось ошибкой |

## Кто что проверяет

| Уровень | Ответственность |
|---|---|
| Локальный API/сервис заданий (вызывающий слой) | Проверяет структуру запроса, обязательные поля, формат идентификаторов и дат; создаёт Job; сопоставляет ключ идемпотентности и параметры; выполняет разрешённые переходы Job |
| Import Tool | Проверяет ограничения запроса INTERMAGNET, контролирует внешний ответ, сохраняет сырой результат и метаданные без подмены содержимого |
| Processing Tool | Проверяет доступность входного набора, поддержку метода и его параметров; сохраняет результат отдельным набором |
| Local Data Query Tool | Проверяет фильтры чтения, предел страницы и локальное наличие набора; читает только локальную БД |
| Репозиторий | Гарантирует целостное сохранение в рамках возможностей выбранной БД и сообщает ошибку хранилища вызывающему слою |

Вызывающий слой выполняет базовую проверку до создания задания, но Tool повторно проверяет условия, связанные с его собственными возможностями и данными. Ошибка параметров не должна инициировать сетевой вызов или запись результата.
