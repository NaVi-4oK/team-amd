# ADR-02: Синхронное выполнение Job ядром

- Дата: 21-11-2026
- Статус: предложено

## Контекст

Первая версия должна выполнять доменный сценарий без отдельной очереди и брокера. Внешние источники могут завершиться ошибкой.

## Решение

Dispatcher синхронно выполняет Tool в рамках вызова `run(job)`. Успех переводит Job по цепочке `Created → Downloading → Processing → Completed`; ошибка Tool переводит активный Job в `Failed`. Повторный запрос с тем же ключом идемпотентности и теми же параметрами должен вернуть прежний Job; тот же ключ с другими параметрами — конфликт. В первой версии ключ хранится в памяти.

## Альтернативы

- Фоновая очередь: лучше подходит для долгих сборов, но требует брокера, воркеров и гарантий доставки.
- Повторно запускать Tool при любой ошибке: может дублировать запросы и скрывать постоянные ошибки доступа/формата.

## Цена

Вызов может долго выполняться; процессная память не обеспечивает идемпотентность между перезапусками. Ограниченные сетевые повторы должны быть политикой конкретного адаптера, а не Dispatcher.

## Пересмотр

Если сборы блокируют API/CLI, становятся длительными или требуется надёжное выполнение после перезапуска.
