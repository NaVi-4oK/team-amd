# ADR-01: Локальная база данных для наборов измерений

- Дата: 2026-11-22
- Статус: предложено

## Контекст

Программа работает на компьютере исследователя. Сырые данные должны оставаться доступными после загрузки и перезапуска программы. Результаты обработки также нужно хранить локально и связывать с исходными наборами. Для чтения сохранённых данных подключение к внешнему API не требуется.

## Решение

Использовать локальное хранилище на компьютере пользователя как единственное постоянное хранилище сырых наборов, обработанных наборов, заданий и их метаданных. Сырые данные и результаты обработки сохраняются как отдельные наборы; обработанный набор содержит ссылку на исходный.

Доступ к хранилищу выполняется через репозитории локального сервиса. Tool загрузки и Tool обработки возвращают данные сервису, а сервис отвечает за их сохранение. Tool чтения использует репозиторий только для выборки данных.

Конкретный движок локальной базы ещё не выбран и должен быть зафиксирован отдельным техническим решением после оценки размера временных рядов и требований к установке.

## Альтернативы

- Хранить данные только в оперативной памяти: после закрытия программы наборы будут потеряны.
- Отправлять сырые данные или результаты на удалённый сервер: это меняет заявленную локальную модель хранения и добавляет внешнюю зависимость.
- Использовать внешнее API как постоянное хранилище: чтение станет зависеть от сети и срока доступности поставщика.

## Последствия

- Загрузка и обработка могут выполняться без отдельного удалённого хранилища.
- При временной недоступности внешнего API уже загруженные данные остаются доступными для чтения и обработки.
- Нужно отдельно определить миграции схемы, резервное копирование, допустимый размер базы и выбор движка.
- Сбой записи не должен помечать Job как `Completed`; состояние и запись набора фиксируются согласованно.

## Пересмотр

После выбора движка базы, определения объёмов данных или появления требования синхронизировать наборы между несколькими устройствами.
