# ADR 0002: Разделить импорт, обработку и чтение на три Tool (изм)

- Статус: принято для проектирования практики 2
- Дата: 2026-11-22

## Контекст

Исследователь отдельно запрашивает получение измерений, обработку ранее сохранённого набора и чтение локальных данных. Это разные операции с разными источниками ошибок и разными последствиями. При импорте программа обращается к INTERMAGNET; две другие операции должны работать с локальной БД.

## Решение

Описать три отдельных Tool:

1. `INTERMAGNET Import Tool` вызывает внешний API и сохраняет сырой набор.
2. `Processing Tool` читает сырой набор и сохраняет отдельный обработанный набор.
3. `Local Data Query Tool` читает сырые или обработанные данные из локальной БД.

Для импорта и обработки создаётся отдельный Job. Импорт использует состояния `Created → Downloading → Completed/Failed`, обработка — `Created → Processing → Completed/Failed`. В обоих случаях запуск может завершиться ошибкой до начала операции: `Created → Failed`. Невалидные переходы запрещены. Чтение — запрос без отдельного Job.

## Последствия

- Обработка не должна повторно запрашивать INTERMAGNET или изменять сырой набор.
- При сбое обработанного набора исходный набор остаётся доступен.
- Для чтения можно использовать локальную копию при отсутствии сети.
- Для каждого Tool отдельно описываются вход, выход, ошибки и ответственность за проверки.
- Точные поля API INTERMAGNET и алгоритмы обработки остаются вне этого решения до подтверждения командой.

## Рассмотренные варианты

- Единый Tool для всех операций: смешивает сетевой импорт, вычисление и чтение, усложняет ошибки и гарантии хранения.
- Обрабатывать сразу во время импорта: не соответствует отдельному запросу пользователя на обработку и не сохраняет самостоятельный исходный набор до обработки.
