# ADR 0001: Локальное однопроцессное приложение

## Контекст и ограничения

Программа предназначена для установки на компьютере исследователя. Импорт обращается к внешнему INTERMAGNET HAPI; обработка и чтение должны работать с локальными наборами. Отдельный локальный HTTP-сервер не требуется, если CLI запускает те же операции внутри программы.

Ограничения: один пользователь и один процесс; внешняя сеть используется только для импорта; база данных локальная. Масштабирование на несколько пользователей, удалённый доступ и раздельное развёртывание компонентов не входят в текущую постановку.

## Решение

Описать систему как одно локальное приложение с CLI, сервисом заданий, реестром трёх Tool и локальным хранилищем. CLI вызывает сервис заданий внутри процесса. Только `INTERMAGNET Import Tool` имеет внешнее сетевое взаимодействие. Локальная БД хранит Job, сырые данные, обработанные результаты и происхождение.

Внешние вызовы HAPI INTERMAGNET, которые использует Import Tool, описаны в `docs/tool-contract.md`. Единая `docs/api/cli.schema.json` описывает команды и ответы CLI.

## Последствия

- Для импорта требуется доступ к INTERMAGNET; обработка и чтение используют локальные данные.
- Для работы CLI не нужен открытый локальный HTTP-порт.
- Программа работает локально для одного исследователя; авторизация нескольких пользователей и разграничение их наборов не входят в контракт.
- Компоненты вызывают друг друга внутри процесса; отдельное развёртывание или сетевое обнаружение Tool не предусмотрено.
- Схему локальной БД и способ хранения больших рядов нужно выбрать до реализации.
- `Completed` допустимо только после сохранения данных и метаданных.

## Рассмотренные варианты

- Несколько локальных сервисов: добавляют межпроцессное взаимодействие и конфигурацию без требования проекта.
- Локальный HTTP API: возможен в будущем, но сейчас не нужен для CLI-варианта и не заменяет внешний HAPI API.
- Удалённая серверная БД: создаёт сетевую зависимость для обработки и чтения, что расходится с локальной моделью.
