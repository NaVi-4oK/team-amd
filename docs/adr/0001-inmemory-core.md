# ADR 0001: Хранить наборы на компьютере исследователя (изм)

- Статус: принято для проектирования практики 2
- Дата: 2026-11-22

## Контекст

По описанию проекта программа работает локально. Сырые данные, полученные из INTERMAGNET, и результаты отдельной обработки должны храниться в локальной базе программы и быть доступны исследователю без повторного получения из внешнего API.

## Решение

Программа использует локальную БД как постоянное хранилище Job, сырых наборов, обработанных наборов и их метаданных. Технология БД пока не выбрана. Сырые и обработанные данные получают разные идентификаторы; результат содержит ссылку на исходный набор. Обработка и чтение выполняются по локальным данным.

Локальный API описывает взаимодействие интерфейса с программой на том же компьютере. Он не заменяет внешний API INTERMAGNET.

## Последствия

- Для импорта нужен внешний доступ к INTERMAGNET; для обработки и чтения — нет.
- Удаление или повреждение локальной БД может привести к потере наборов; резервное копирование в рамках P2 не проектируется.
- Схему БД и способ хранения больших исходных ответов нужно выбрать до реализации.
- Состояние `Completed` допустимо только после сохранения результата и метаданных.

## Рассмотренные варианты

- Внешняя серверная БД: противоречит требованию локального хранения и создаёт сетевую зависимость для обработки/чтения.
- Хранить только обработанные данные: теряется требуемый доступ к скачанным сырым данным.
- Перезаписывать сырой набор результатом: теряется исходный материал и возможность повторной интерпретации.
