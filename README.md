# Локальная программа обработки геомагнитных данных

## Проблема

Исследователям необходимо получать геомагнитные измерения
обсерваторий, сохранять их происхождение, выполнять обработку
и получать результаты для дальнейшего научного анализа.

Программа предоставляет единый способ получения данных
INTERMAGNET, их локального хранения, обработки и чтения.

## Для кого

Исследователи и аналитики геофизических данных.

## Возможности проекта

- Получение сырых геомагнитных данных из INTERMAGNET HAPI.
- Выбор обсерватории, publication state, cadence, компонент
  и временного периода.
- Создание отдельных Job для импорта и обработки.
- Просмотр состояния и результата Job.
- Защита от повторного выполнения через ключи идемпотентности.
- Сохранение исходных данных и метаданных происхождения.
- Обработка выбранного сырого набора отдельным методом.
- Сохранение обработанного результата без изменения исходного.
- Получение локальных наборов по идентификатору и фильтрам.
- Стабильная пагинация результатов.
- Обработка ошибок запроса, источника и выполнения задания.

## Что не входит

- Обучение нейросетей и прогнозирование временных рядов.
- Автоматическое восстановление пропусков.
- Автоматическое удаление необычных измерений.
- Карта и трёхмерная визуализация.
- Регистрация пользователей и разграничение прав доступа.
- Собственный локальный HTTP API.
- Распределённая очередь заданий и удалённые worker.
- Отмена выполняющихся Job.

## Текущее состояние — практика 3

Реализовано доменное ядро на Python:

- Job с контролем переходов состояний.
- Общий программный контракт Tool.
- Registry для регистрации и поиска операций.
- Dispatcher для управления выполнением.
- Хранилища Job и наборов данных в оперативной памяти.
- INTERMAGNET Import Tool.
- Processing Tool.
- Local Data Query Tool.
- Идемпотентность и обработка прерванных заданий.
- Модульные и интеграционные тесты.

Import Tool проверяется через тестовый адаптер INTERMAGNET.
Реальное сетевое взаимодействие пока не реализовано.

Processing Tool поддерживает демонстрационный метод
`count_records`, подсчитывающий записи сырого набора.
Полноценные научные методы будут добавлены отдельно.

Постоянное хранение, пользовательский CLI и реальное
восстановление данных после перезапуска относятся
к следующим этапам разработки.

## Требования к окружению

- Python 3.9 или новее.
- Дополнительные библиотеки для текущего ядра не требуются.
- Для запуска тестов не нужны интернет и база данных.

## Запуск тестов

Из корневой папки репозитория:

```bash
python -m unittest discover -s tests -v
```

На macOS и Linux при необходимости можно использовать:

```bash
python3 -m unittest discover -s tests -v
```

На момент завершения реализации практики 3 успешно
пройдены 72 теста.

Проверяются обычные пути Job, недопустимые переходы,
идемпотентность, Registry, Dispatcher, ошибки Tool,
хранилища, пагинация и полный сценарий
«импорт → обработка → чтение результата».

Злодейство З3 неприменимо, поскольку отмена и удаление Job
не предусмотрены. З2 проверяется через имитацию
восстановления незавершённого задания в памяти.
