# Проверка контракта картами К1–К10

Черновик: формулировки следует сверить с актуальной колодой `tasks/p2_poker/README.md` перед сдачей.

| Карта | Ответ контракта |
|---|---|
| К1 Двойной клик | `Idempotency-Key`; одинаковые параметры возвращают тот же Job; иные параметры с тем же ключом дают `409` — `api/openapi.yaml`, `POST /jobs`; ADR-0002. |
| К2 Неверный запрос | `400 invalid_parameters` с `details.field`; Job не создаётся, Tool не вызывается — `api/openapi.yaml`, схема `ApiError`; Tool contract. |
| К3 Неизвестный источник | `unknown_operation`; Registry не возвращает Tool, выполнение не начинается — Tool contract и API error. |
| К4 Повтор после ошибки | Ошибка завершает исходный Job в `Failed`; повторный сбор требует нового ключа и создаёт новый Job — ADR-0002. |
| К5 Частичный ответ | Результат отмечает `coverage=partial`; отчёт перечисляет пропуски при известном шаге, иначе покрытие `unknown` — Tool contract. |
| К6 Отмена | Не поддерживается в первой версии; у Job нет перехода в состояние отмены — ADR-0002 и диаграмма. |
| К7 Секрет в ошибке | Сообщение об ошибке не содержит токенов/секретов; `401` преобразуется в `access_denied` — Tool contract и требования сценария 4. |
| К8 Неверная структура ответа | Tool возвращает `invalid_source_response`; Job переходит в `Failed`, частичный результат не публикуется — Tool contract и диаграмма. |
| К9 Чрезмерный ответ/таймаут | Источник ограничен таймаутом и лимитом чтения; ошибка `source_unavailable` или `response_too_large`, бесконечных повторов нет — Tool contract. |
| К10 Внешний сервис | Адаптер скрывает протокол и формат источника; `Dispatcher` зависит только от контракта Tool; конкретные источники заменяемы — архитектурная схема, ADR-0001. |

## Что предложил ИИ

Промпт: «Мы делаем агрегатор геофизических данных. Проверь контракты Job, Dispatcher и Tool на три цепочки вызовов, которые могут привести к некорректному состоянию или потере данных. Для каждой укажи предусловия, ожидаемый отказ и тест».

1. **Завершение без результата:** нельзя перевести Job в `Completed` без результата; защита — единый метод `complete(result)`; добавить тест.
2. **Ошибка Tool оставила Job в `Downloading`:** Dispatcher обязан перевести активный Job в `Failed`; добавить тест на исключение Tool.
3. **Неизвестный Tool вызван после смены состояния:** Registry ищет Tool до начала выполнения; при неизвестной операции Job не создаётся/остаётся `Created`; добавить тест.

Эти находки приняты как проверки реализации практики 3.
